# KijaniKiosk CI Pipeline — Credential Security Audit

## 1. Jenkins credential storage

**Implementation evidence:** The Publish stage retrieves the `nexus-publisher` credential using Jenkins credential binding. The publishing username and password are not intentionally hardcoded in the Jenkinsfile.

## 2. Temporary npm configuration

**Implementation evidence:** The Publish stage creates a temporary `.npmrc` inside the publishing shell and uses an exit trap to remove it. This reduces the risk of leaving registry authentication configuration in the workspace.

## 3. Console-log masking

**Observed evidence:** The successful pipeline log showed Jenkins masking the password variable, and the publishing command completed successfully. The captured log should be reviewed to ensure no credentials appear in plain text.

## 4. Source-control review

**Checks performed:** Tracked files and Git history were inspected for credential-like patterns and `.npmrc` files. Record the actual scan results before marking this check complete. Pattern matches must be reviewed because variable names and examples can produce false positives.

## 5. Nexus permissions and Jenkins access

**Manual verification required:** Confirm that the Nexus publishing account has only the permissions needed for the intended npm hosted repository, and that Jenkins credentials are accessible only to authorized users and jobs.

## 6. Rotation and incident response

**Manual verification required:** Confirm the credential rotation process. If a real credential is ever exposed, revoke or rotate it promptly and review the relevant logs and repository history.

## Overall assessment

The pipeline uses Jenkins credential binding, masked console output, and temporary npm configuration. These controls reduce accidental exposure, but they do not independently prove that every repository revision, build log, Jenkins permission, and Nexus account is free of credential exposure. The remaining manual checks must be completed before declaring the audit fully verified.

**Security reminder:** Never include actual passwords, tokens, encoded authentication values, or other secrets in committed evidence or pull-request descriptions.
